## 1. 결론
- 1.1의 세 기능(F22 속도 개선, F20 자동 업데이트, F23 후원)과 U4 "바뀐 점" 창을 만들었고, 자동 테스트 72개가 모두 통과 (개인 PC에서 2026-11-25 다시 실행해도 72개 통과)
- 업데이트는 실제 GitHub의 1.0.0 릴리스로 끝까지 확인: 새 버전 알림 → 바뀐 점 → 받기(44.4MB) → 해시 확인 통과. 설치 파일로 덮어 설치하는 것도 확인(7절): 고친 뒤에는 관리자 확인 창 말고 아무 창도 뜨지 않고 또또집이 다시 실행됨
- 압축 크기는 6가지 모두 반디집보다 작음. 속도는 3번 다시 재 보니 반디집과 비슷한 수준(빠른 곳 1개, 같은 곳 1개, 느린 곳 4개). 측정하던 때 PC가 바빴던 흔적이 있어 배포 전 한 번 더 잼
- **후원은 GitHub Sponsors 하나로 넣음** (2026-11-25 결정). 카카오페이는 사업자 계좌로 송금 코드(QR)를 만들 수 없어 1.1에서 제외. 정보 창·도구 모음·첫 화면에서 GitHub Sponsors 버튼 하나만 보이고, 눌렀을 때 실제 Sponsors 페이지가 열리는 것까지 개인 PC에서 확인
- **알려진 이슈**: Windows 스마트 앱 컨트롤이 켜진 PC에서는 서명 없는 또또집이 막혀 실행되지 않음. 코드 서명은 1.2로 미루고, 1.1 릴리스 소개글에 안내문을 넣음 (9절)

## 3. 속도 측정 (3번씩 재서 가장 빠른 값)

같은 데이터(파일 5,066개, 828MB), 반디집 7.39와 같은 수준으로 비교. `tools/benchmark.ps1`.

| 형식·수준 | 1.0.0 | 1.1 | 반디집 | 1.1 vs 반디집 |
|---|---|---|---|---|
| ZIP 빠르게 | 19.4초, 350MB | 23.2초, 350MB | 21.9초, 371MB | 6% 느림, 6% 작음 |
| ZIP 보통 | 19.7초, 334MB | 20.0초, 334MB | 20.0초, 345MB | 같음, 3% 작음 |
| ZIP 최고 | 99.3초, 328MB | **51.5초**, 330MB | 47.5초, 341MB | 8% 느림, 3% 작음 |
| 7Z 빠르게 | 20.6초, 274MB | **18.5초, 264MB** | 20.6초, 266MB | 10% 빠름, 1% 작음 |
| 7Z 보통 | 65.4초, 220MB | 67.6초, **181MB** | 59.1초, 190MB | 14% 느림, 5% 작음 |
| 7Z 최고 | 94.0초, 196MB | 87.2초, **177MB** | 73.4초, 179MB | 19% 느림, 1% 작음 |

풀기(같은 압축 파일을 풀어서 비교): 6가지 모두 또또집이 9-41% 빠름 (예: 7Z 보통 46.6초 vs 78.7초).

읽는 법:
- **크기**는 설계대로 줄었음 (7Z 보통 220 → 181MB, 7Z 최고 196 → 177MB). 6가지 모두 반디집보다 작음
- **속도**는 설계 때 한 번 잰 값(7Z 보통 58초, 7Z 최고 82초, ZIP 최고 41초)보다 느리게 나옴. 이번 측정 때 PC가 바빴던 것으로 보임
  - 반디집도 설계 때보다 느렸고(7Z 보통 52.5 → 59.1초), 풀기는 양쪽 모두 평소보다 훨씬 오래 걸림
  - 7Z 최고는 표를 만든 뒤 따로 3번 다시 쟀더니 87-98초
- 그래서 속도 비교는 **배포 직전 다른 작업이 없는 상태에서 한 번 더 재서** 릴리스 소개글에 넣음

### 3.1 측정 중 발견한 문제
- 7Z 최고 3번 중 1번이 **메모리 부족(0x8007000E)** 으로 실패. 다시 3번 돌렸을 때는 모두 성공(사용 메모리 최대 313MB). 측정하던 때 PC 메모리가 부족했던 것으로 보임
  - 오류 문구를 "압축 중 오류가 났습니다 (0x8007000E)" → **"메모리가 부족해 압축하지 못했습니다. 다른 프로그램을 닫거나 압축 수준을 낮춰 다시 해 보세요."** 로 바꿈
  - 측정 스크립트가 실패한 회차를 "가장 빠른 값"으로 잡던 문제를 고침 (실패하면 멈추고 알림)

## 5. 개발 중 발견해서 고친 문제
1. **정보 창을 열면 프로그램이 꺼짐**: 업데이트 기능의 시작 순서 문제(인터넷 연결 준비가 버전 값보다 먼저 만들어져 빈 값을 읽음). 같은 이유로 시작할 때 새 버전 확인도 조용히 실패하고 있었음 → 순서를 바로잡고, 이 부분을 실제로 거치는 자동 테스트 추가
2. **숫자 뒤 조사**: "1.0.0이 나왔습니다", "1.1.0로 업데이트" 처럼 버전 끝 숫자에 따라 조사가 틀림 → "새 버전이 나왔습니다: 1.0.0", "1.1.0 버전으로 업데이트했습니다." 로 바꿈
3. **받기 시간 초과**: GitHub 응답이 없어 시간이 다 되면 "취소"로 처리되어 아무 말 없이 끝남 → "업데이트를 받지 못했습니다. 인터넷 연결을 확인해 주세요." 안내
4. **후원 문구 줄바꿈**: 정보 창에서 "요."만 다음 줄로 넘어감 → "도움이 되셨다면 후원으로 응원해 주세요." 로 줄임
5. **테스트 빌드 오류**: 테스트 프로젝트가 WPF 앱을 참조하면서 기본 `System.IO` 가져오기가 빠짐 → 테스트 프로젝트에 직접 추가

## 7. 설치 파일 업데이트 시험 (이 PC, 1.0.0 → 1.1.0)

앱이 하는 것과 같은 방법(관리자 확인 창 → 조용히 설치)으로 설치 파일을 실행.

| 회차 | 결과 |
|---|---|
| 1차 (고치기 전, `/SILENT /UPDATE`) | 탐색기가 우클릭 DLL을 쓰고 있어 설치 프로그램이 탐색기를 닫으려다 **실패**. "응용 프로그램을 닫지 못했습니다" 창 3번 → [무시] → DLL은 재부팅 때 바꾸기로 하고 "지금 다시 시작할까요?" 창 → [아니요]. 나머지는 1.1.0으로 설치, 설치 후 또또집이 저절로 다시 실행됨 |
| 2차 (고친 뒤, `/SILENT /UPDATE /NORESTART`) | 관리자 확인 창 말고는 **아무 창도 뜨지 않음**. 탐색기 건드리지 않음, 재부팅 필요 없음, 10초 만에 설치 후 또또집 다시 실행됨 |

원인: 우클릭 DLL은 1.0 이후 바뀌지 않았는데, 빌드할 때마다 파일 안의 시각 정보가 달라져서 설치 프로그램이 매번 "새 파일"로 보고 바꾸려 함. 탐색기는 Restart Manager로 닫히지 않음.

고친 것:
1. **DLL을 항상 같은 내용으로 빌드** (`/Brepro`): 두 번 빌드해 해시가 같은 것 확인
2. **바뀐 경우에만 교체**: 빌드 때 DLL 해시를 설치 파일에 넣고, 설치된 DLL과 같으면 건너뜀. 대부분의 업데이트는 탐색기와 상관없이 끝남
3. **탐색기를 닫으려 하지 않음**: 실행 중인 또또집(.exe)만 닫음. DLL이 실제로 바뀐 드문 경우에는 다음 재부팅 때 교체
4. **자동 업데이트는 재시작 창 없음**: 앱이 설치 파일을 `/NORESTART`로 실행

참고:
- 1.0.0의 DLL은 이 방식 전에 만든 것이라, 1.0.0 → 1.1.0 업데이트 때 한 번은 교체됨 (탐색기가 쓰는 중이면 다음 재부팅 때)
- 이 PC에는 1차 시험 때 예약된 교체(1차 설치 파일의 DLL)가 남아 있음. 다음 재부팅 때 그 DLL로 바뀌는데, 소스가 같아 동작은 같고 다음 업데이트 때 한 번 더 교체됨

## 9. 알려진 이슈와 릴리스 안내문

### 스마트 앱 컨트롤 (코드 서명 없음)
- Windows 11을 새로 설치한 PC에서 켜지는 **스마트 앱 컨트롤**은 서명 없는 프로그램을 막음. 또또집은 코드 서명이 없어서, 이 기능이 켜진 PC에서는 실행·설치가 막힘 (개인 PC에서 실제로 막히는 것을 확인함)
- 1.0.0도 같은 조건이라 1.1에서 나빠지는 것은 없음. 코드 서명(유료)은 1.2 범위로 미룸
- 참고: 스마트 앱 컨트롤은 처음 평가 모드로 돌다 저절로 꺼지는 경우가 많고, 기존 PC를 업그레이드한 경우는 꺼져 있음. 영향 받는 사용자는 일부로 추정(수치 미확인)
