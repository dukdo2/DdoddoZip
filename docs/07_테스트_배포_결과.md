## 2. 고친 문제: 작은 파일이 많으면 풀기가 느림

- 증상: 작은 파일 5,000개를 풀 때 15.8초, 반디집은 4.9초
- 원인: 이 PC에서는 보안 프로그램이 새 파일마다 검사해서 **파일 하나 만드는 데 약 1.5ms**가 걸림. 또또집은 파일을 하나씩 차례로 만들고, 다 쓴 파일을 다시 열어 날짜를 고쳐서 이 비용을 두 번 냈음
- 고친 방법
  - 파일을 닫기 전에 날짜를 넣음 (다시 열지 않음)
  - 이미 만든 폴더는 다시 확인하지 않음
  - 256KB 이하 파일은 메모리에 풀어 두고, 디스크에 만드는 일은 뒤에서 4개를 동시에 처리
- 결과: **15.8초 → 4.4초** (반디집 4.9-5.5초). 이름·크기·날짜·내용 모두 같음
- 큰 파일은 지금처럼 바로 디스크에 씀. 1MB 이상이면 미리 자리를 잡아 둬서 조각이 덜 생기고 공간 부족을 빨리 알 수 있음

## 3. 설치 파일

| 항목 | 내용 |
|---|---|
| 파일 | `DdoddoZip-1.0.0-setup.exe` (45.2MB) |
| 만드는 도구 | Inno Setup 6.7.3 (`installer/DdoddoZip.iss`, `build.ps1 -Installer`) |
| 설치 위치 | `C:\Program Files\DdoddoZip` (모든 사용자, 관리자 권한) |
| .NET 런타임 | 포함. 받는 PC에 아무것도 깔려 있지 않아도 실행 |
| 설치 화면 | 한국어, 바탕 화면 바로 가기(선택), 끝나면 "또또집 실행" |
| 설치하면 | 시작 메뉴 등록, 우클릭 메뉴 6개, 연결 프로그램, 제어판 "앱 제거" 목록 |
| 제거하면 | 파일, 우클릭 메뉴, 연결 프로그램 등록 모두 지움. 설정 파일(`%APPDATA%\DdoddoZip`)은 남김 |
| 업데이트 | 같은 설치 파일을 다시 실행하면 덮어씀. 탐색기가 우클릭 DLL을 쓰고 있으면 탐색기를 잠시 닫았다가 다시 엶 |
| 버전 | 1.0.0 (`Directory.Build.props`) |
| 라이선스 | `LICENSE.txt` 추가 (MIT + 7-Zip 안내), 설치 폴더에도 복사 |

### 확인한 것
| 항목 | 결과 |
|---|---|
| 조용히 설치 (`/SILENT`) | 성공, 재부팅 필요 없음 |
| 설치 후 우클릭 메뉴 | 텍스트 파일: 압축 3개 / ZIP: 풀기 3개 (Program Files의 DLL에서) |
| 제거 | 폴더·레지스트리·제거 목록 모두 깨끗하게 지워짐. 원래 있던 "압축 폴더" 연결은 그대로 |
| 다시 설치 | 성공 (지금 이 PC에 설치되어 있음) |
| 개발용 설치 | 등록 해제하고 `%LOCALAPPDATA%\Programs\DdoddoZip` 폴더 삭제 |

### 아직 확인하지 못한 것
- **5GB ZIP 풀기 314초**: 같은 크기 7Z(106초)의 3배. 검사는 45초라 디스크에 쓰는 쪽이 느렸는데, 그 시간에 설치 파일 빌드·설치 시험을 같이 돌려서 디스크가 겹쳤을 수 있음. 따로 다시 재 봐야 함 → 다시 잰 결과 정상 ([08_검수_결과.md](08_검수_결과.md) 2절)
- **탐색기가 DLL을 쓰는 중에 업데이트·제거**: 시험할 때는 탐색기가 DLL을 불러오지 않은 상태였음. 우클릭 메뉴를 한 번 띄운 뒤 다시 설치해 봐야 함
- **다른 PC에서 설치**: .NET이 없는 PC, Windows 10에서 설치해 보기
- **코드 서명 없음**: 처음 받은 사람은 "Windows의 PC 보호"(SmartScreen) 경고에서 "추가 정보 → 실행"을 눌러야 함. 서명 인증서는 유료(연 수십만 원)라 지인 배포 단계에서는 생략 제안
