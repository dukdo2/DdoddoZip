## 1. 압축 엔진 비교 (D2)

| 후보 | 지원 형식 | 7Z 압축 | RAR5 해제 | ZIP 암호(AES) | 라이선스 | 평가 |
|---|---|---|---|---|---|---|
| **7z.dll (7-Zip 공식)** | 기획서 형식 전부 | O | O | O | LGPL + unRAR 조건 | **추천** |
| SharpCompress (순수 C#) | 대부분 | X (해제만) | O | 일부 | MIT | 7Z 압축 불가로 탈락 |
| System.IO.Compression (.NET 기본) | ZIP, GZ, TAR | X | X | X | MIT | 기능 부족 |
| libarchive | 대부분 | O | O | O | BSD | C 라이브러리라 연결 작업이 더 큼 |

### 7z.dll 연결 방식
- 기존 C# 연결 라이브러리(SevenZipSharp)는 업데이트가 멈춰 있어서, **필요한 부분만 직접 연결 모듈을 만든다**. 포트폴리오로도 보여주기 좋은 부분.
- 7z.dll은 7-Zip 공식 사이트에서 받은 원본을 그대로 동봉(수정하지 않음). 4단계 시작 시 다운로드 승인 요청.
- **한글 파일명(F06)**: ZIP의 파일 목록을 직접 읽어 UTF-8인지 CP949인지 판별한 뒤, 7z.dll에 문자 코드(`cp=949` 또는 UTF-8)를 지정해서 연다.

### 라이선스 지키기
- 7z.dll은 LGPL: 수정 없이 별도 DLL로 동봉하고, 라이선스 문서와 출처를 함께 배포.
- unRAR 조건: RAR 압축 기능을 만들지 않음 (기획서와 일치).
- 또또집 코드: MIT 라이선스로 GitHub 공개.

## 2. 우클릭 메뉴 설계 (D3, F10)

### 방식 비교
| 방식 | 메뉴 글자에 파일 이름 | 여러 파일 한 번에 | 난이도 | 평가 |
|---|---|---|---|---|
| 레지스트리에 고정 메뉴만 등록 | X ("ZIP으로 압축하기"로 고정) | 파일마다 프로그램이 따로 실행되어 합치는 처리 필요 | 쉬움 | 기획 요구 미충족 |
| **C++ 셸 확장 DLL** | O ("01_기획서.zip으로 압축하기") | O (선택한 파일 목록을 한 번에 받음) | 보통 | **추천**, 반디집과 같은 방식 |
| C# 셸 확장 | O | O | 보통 | 탐색기 안에 .NET이 올라가 충돌 위험, MS 비권장 |

### 동작 흐름
1. 탐색기에서 파일을 고르고 우클릭 → "더 많은 옵션 표시"
2. 셸 확장 DLL이 선택 목록을 보고 메뉴 글자를 만든다 (기획서 F10 이름 규칙)
3. 메뉴를 누르면 DLL은 선택 목록을 임시 파일에 적고 `DdoddoZip.exe quickzip --list <임시 파일>`을 실행만 하고 끝난다
4. DdoddoZip.exe가 작은 진행률 창을 띄우고 ZIP을 만든 뒤 자동으로 닫힌다

> DLL은 "메뉴 글자 만들기 + 프로그램 실행"만 한다. 실제 압축은 전부 C# 쪽에서 하므로 탐색기가 멈추거나 꺼질 위험이 적다.

### 등록 위치
- 사용자 단위 등록 (`HKEY_CURRENT_USER\Software\Classes`), 관리자 권한 없이 설치/삭제 가능
- 대상: 모든 파일과 폴더

## 3. 프로그램 구조

```
DdoddoZip/
├─ src/
│  ├─ DdoddoZip.Core/        압축 엔진 연결, 인코딩 판별, 안전한 경로 검사, 이름 규칙 (화면과 무관한 핵심)
│  ├─ DdoddoZip.App/         WPF 화면 (메인 창, 압축 창, 진행률 창, 암호·덮어쓰기 창)
│  ├─ DdoddoZip.Cli/         명령줄 도구 (4단계 동작 확인용, 배포에도 포함 가능)
│  └─ DdoddoZip.ShellExt/    C++ 우클릭 메뉴 DLL
├─ tests/
│  └─ DdoddoZip.Tests/       자동 테스트 (xUnit)
├─ third_party/7zip/         7z.dll 원본과 라이선스 문서
├─ installer/                Inno Setup 스크립트
└─ docs/                     기획서, 설계서
```

### 핵심 모듈 (DdoddoZip.Core)
| 모듈 | 하는 일 | 관련 기능 |
|---|---|---|
| ArchiveReader | 압축 파일 열기, 목록 읽기 | F01 |
| Extractor | 해제, 진행률, 취소, 덮어쓰기 질문 | F02, F05, F08 |
| Compressor | 압축(형식, 압축 수준) | F03, F10 |
| EncodingDetector | ZIP 파일명 UTF-8/CP949 판별 | F06 |
| PathGuard | 위험 경로 차단(Zip Slip), 긴 경로 처리 | F09 |
| NamePolicy | "○○.zip", "docs (2).zip" 이름 규칙 | F10 |

- 화면이 멈추지 않도록 압축/해제는 백그라운드에서 실행하고, 진행률만 화면으로 전달 (F05)
- 암호·덮어쓰기 질문은 Core가 "질문 요청"을 보내고 화면이 답하는 구조라서 명령줄과 화면 양쪽에서 같은 코드를 씀

## 4. 품질 기준 달성 방법

| 기준 | 방법 |
|---|---|
| 1초 이내 실행 | ReadyToRun 미리 컴파일, 시작 시 7z.dll 늦게 불러오기 |
| 대용량 | 파일 목록을 화면에 보일 부분만 그리기(가상화), 스트림 처리로 메모리 일정 유지 |
| 긴 경로 | 앱 설정에 긴 경로 허용 선언 |
| 깨진 파일 | 엔진 오류를 모두 잡아 안내 메시지로 변환, 자동 테스트에 깨진 샘플 포함 |

## 6. 테스트 계획 (요약)
- **자동 테스트**: 형식별 압축 후 해제해서 원본과 같은지 비교, 한글 이름(CP949/UTF-8) 샘플, 위험 경로 샘플, 암호 파일, 깨진 파일
- **수동 테스트**: 우클릭 메뉴, 끌어다 놓기, 대용량(4GB 이상) 파일
